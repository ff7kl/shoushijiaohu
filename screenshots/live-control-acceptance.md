# 真人控制接入与验收

## 使用
开启摄像头，左手完整入镜，选择“自然中立 / 伸展 / 弯曲校准”。每步点击开始采样并保持约2秒：先自然放松手指并保持舒适掌面方向，再舒适伸展，最后舒适弯曲。不要求极限伸直或握紧。五指各自中立两侧跨度须至少0.025；不足时保留旧校准并单独重试。手指中立区占每侧跨度15%。未校准的通道保持中立。

拇指/食指分别控制左/右臂，无名指/小指分别控制左/右腿：伸展后摆，弯曲前摆。中指从中立到弯曲控制整体提身，伸展不向地面下拉。脚随迈步输入抬高，回中落脚。掌面相对校准方向控制 yaw/pitch。四肢灵敏度、四肢范围、头部灵敏度、头部范围独立调整。范围为动作最大行程的比例。

使用世界关键点（可用时）上的腕部、食指/中指/无名指/小指掌指关节构建掌面；通过相对角度最短差处理±π跨界。退化掌面回中，丢手超过300ms回中，重入沿dt平滑与速率限制过渡。右手提灯与原捏合调灯高保持原逻辑，无新增手势。

## 已验证
- 数值断言：死区、正负行程、限幅、无校准保护、掌面旋转和退化、±π跨界、不同帧率dt平滑一致性、速率限制。
- 浏览器合成关键点：真实UI三步校准、四肢独立正负目标、左右腿相反目标、掌面yaw/pitch、保持姿态、双手同时事件、遮挡丢失回中、反向重入限速。
- 原四角色40姿态回归通过：骨长、头颈独立性、脚底、灯具安全。
- npm run check 与 npm run build 通过。

上述为合成关键点和浏览器测试，不代表真人摄像头识别验收。

## 性能
90帧浏览器合成输入样本：渲染提交P50 2.5ms、P95 3.2ms；帧间隔P50 16.7ms、P95 17.5ms。这是CPU渲染提交时间，不是GPU完成时间，也未包含真人推理。当前不能据此判断摄像头场景是否需要Worker，因此未引入Worker，也未叠加新滤波链。运行时显示推理、推理P95、追踪更新间隔、渲染提交与帧间隔；真实推理数据可从window.handPerformance读取。

## 本轮复核

当前 actionInput 已输出统一9通道，后4项并非固定0。补充 stepHeight：无名指/小指各自经过连续正弦抬脚弧线，回中和端点额外抬脚量回落为0，后摆附加抬脚更小；基础IK摆动仍会改变脚的高度，不保证前摆极端位置完全贴地。未使用时间循环。

新增 guardPalm：连续输入中单次 yaw 突变超过1.2rad 或 pitch超过0.9rad 拒绝该次掌面，角度跨±π使用最短差；输出继续通过dt平滑和速率限制。真人摄像头动作与光照测试仍待用户完成。

提交仅包含动作相关运行代码、必要的小型角色代码依赖和验收说明/数值；已有本地模型、贴图、参考图、设计草稿不纳入本轮提交。不部署、不推送。


## 掌面状态与校准修复

最后有效掌面、最后有效时间、本帧有效性、最近非退化候选时间分别保存。异常候选持续到来时不会因有效时间变旧而自动放行；拒绝帧不覆盖参考、不刷新有效时间。超过1秒没有非退化候选后允许重建参考，实际输出仍经过dt平滑和速率限制。

单指校准只更新该指范围，不改变头部基准。完整校准完成或点击“头部回中”才更新头部基准；回中要求当前掌面有效且未过期。部分校准失败明确列出手指，保留原有有效范围。未校准通道明确提示需要校准。四肢指示器使用−1～+1范围，中指使用0～1。

新增序列断言：持续2秒异常、正常恢复、丢失后重新建立参考且输出限速、单指重校准头部基准不变、部分失败保留有效范围。浏览器使用合成关键点驱动实际handtracking事件和校准按钮，检查单指失败提示、头部基准保持、连续异常拒绝与正常恢复；不等同摄像头真人测试。真人结果仍为待用户测试。
